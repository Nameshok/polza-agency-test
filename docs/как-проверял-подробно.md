# Как я проверял — подробный журнал

В README краткая версия, как и просили в задании. Здесь то же самое по шагам, с цифрами,
плюс ошибки, которые нашлись по ходу. Живой вывод команд — `run-output.txt`
и `report-output.txt` в этой же папке, оба сняты с чистой базы (`npm run db:reset`).

1. **Идемпотентность.** Запустил оба загрузчика по два раза. Первый прогон: 994 записи
   из API, 189 из CSV. Второй: `вставлено 0, обновлено 0, без изменений 1000 / 198`
   (API / CSV), число компаний не изменилось — 1183. Это первое, что я проверяю после
   любой правки загрузчика: «работает» и «не портит при повторе» — разные утверждения.

2. **Загрузка с нуля, а не поверх старого.** Дважды ловил себя на том, что радуюсь
   результату, оставшемуся от предыдущего прогона. Поэтому появился `npm run db:reset`,
   и все цифры в отчётах сняты после него.

3. **Сверка страницы с базой.** Поиск «Восток» с фильтром по Москве дал одну компанию —
   выглядело как баг фильтра. Выполнил то же условие в psql: там тоже одна. Совпало,
   значит страница не врёт, просто данные такие.

4. **Поиск ломал специально.** `%`, `_`, `' OR 1=1 --`, кириллица с кавычками
   («ООО «Заря Тех»» — та самая строка с битой кодировкой, после ремонта находится),
   `?page=abc`, `?page=-3`, `?page=99999`, несуществующий город. Ничего не упало;
   `%` и `_` дают 0 совпадений, то есть экранирование работает, а не пропускает шаблон
   в SQL; `?page=99999` прижимается к последней странице.

5. **Мобильная вёрстка — замером, а не скриншотом.** На 390 px: `innerWidth = 390`,
   `documentElement.scrollWidth = clientWidth = 375` (горизонтального выезда нет),
   при этом контейнер таблицы внутри себя 900 против 327 — таблица скроллится сама.
   По скриншоту такое не отличить от обрезанного контента.

6. **Продакшен-сборка, а не только dev.** `npm run build` проходит, и в отчёте сборки
   `/companies` помечен как динамический маршрут — то есть `force-dynamic` действительно
   работает. Если бы страница попала в статику, поиск отдавал бы всем одну и ту же
   выборку. На `npm start` проверил те же шесть запросов, что и в dev: результаты
   совпали.

7. **Консоль браузера.** Была одна ошибка — 404 на `favicon.ico`. Добавил `app/icon.svg`,
   ошибок не осталось. Предупреждения про preload CSS приходили от моих же тестовых
   `fetch` в dev-режиме, к странице отношения не имеют.

8. **`tsc --noEmit`** — чисто. По ходу он поймал два реальных промаха: необработанный
   `undefined` при чтении `searchParams` и несовпадение типа строки, приходящей из БД.

9. **Тесты на реальных значениях из выгрузки — и они нашли мою ошибку.** В регулярке,
   срезающей «ООО»/«АО»/«ИП» из названия, стояла граница слова `\b`. В JavaScript без
   флага `/u` она считается по латинице, поэтому между `ооо` и пробелом границы нет —
   форма не срезалась вообще, и функция молча делала не то, что написано в её имени.
   На данных задания дубли всё равно находились: обе стороны сравнения были испорчены
   одинаково. Руками это не проявилось бы. После этого в тестах на каждую правовую форму
   стоит проверка точного ожидаемого значения, а не равенства двух вызовов.

10. **Проверка инвариантов на живой базе** (`npm run test:db`): обеднённая версия
    существующей записи ничего не затирает; настоящий ноль отзывов, наоборот, старое
    значение перезаписывает; повтор той же записи даёт `unchanged`; ограничения схемы
    отбивают рейтинг вне шкалы и отрицательное число отзывов. Всё внутри транзакции,
    которая откатывается, — база после проверки не меняется.

11. **Воспроизводимость проверял на чистом клоне из GitHub, а не в рабочей папке.**
    Без `.env` `docker compose` осознанно не стартует и говорит, что делать. По инструкции
    из README всё поднимается, загрузка даёт те же 994 + 189, тесты и проверка типов
    проходят, страница отдаёт те же выборки.
